# Lost Dream Messenger — Flutter-клиент

Кроссплатформенный клиент (Android, iOS, macOS, Windows, Linux, web) к Django-бэкенду
[lost-dream-messenger](https://github.com/artemmj/lost-dream-messenger): личные и групповые чаты, real-time через
WebSocket, presence, счётчики непрочитанного, JWT-авторизация.

Эталон поведения — **Vue-фронтенд того же бэкенда** (`../lost-dream-messenger-server/frontend/`):
тот же сценарий, тот же контракт, та же реакция на события. Клиент повторяет его поведение, а не код
(см. [AGENTS.md](AGENTS.md), раздел 8 «Паритет с веб-эталоном»).

> **Статус: функционально завершённый клиент.** Все дефекты №1–№20, №25 и №27–№29 закрыты,
> функциональные пробелы эталона (presence, переименование группы, удаление чата, добавление
> участников, пагинация истории, error-кадры, системный «назад», жизненный цикл приложения)
> реализованы. `flutter analyze` — 0 замечаний, `flutter test` — проходит.
> Что осталось — платформенные конфиги целей (№21–№24), безопасность хранения токена (№26),
> тестовое покрытие (1 смоук-тест на весь клиент) и четыре пункта UX-паритета в списке чатов
> (№30–№33) и инженерный долг (тесты №35, env-конфиг №34, вызовы `Api` из экранов №37 и др.).
> Полная опись — [AGENTS.md](AGENTS.md), разделы 7, 9 и 10.

## Запуск

1. Поднять бэкенд: `cd ../lost-dream-messenger-server && docker compose up` (Postgres, Redis, Daphne на `:8000`).
2. Проверить хост в `lib/config.dart` (`AppConfig.host`):

   | Цель | Хост |
   |------|------|
   | Эмулятор Android | `10.0.2.2:8000` (уже по умолчанию) |
   | Симулятор iOS / macOS | `127.0.0.1:8000` |
   | Реальное устройство | IP машины в локальной сети |

3. `flutter pub get && flutter run -d <device>`.

Хост зашит константой времени компиляции, поэтому смена окружения — это правка файла.
`--dart-define` не поддерживается (№34 в AGENTS.md).

## Что работает

**Сессия**
- вход и регистрация, хранение пары JWT, авто-refresh по 401 с одним повтором запроса;
- регистрация больше не делает лишний `login` — токены берутся из ответа 201 (№14);
- реактивный переход Логин ↔ Список чатов через `_Boot` + `watch<AuthState>`, вход/выход без ручной навигации;
- выход из аккаунта: `clearAll()` закрывает оба сокета и обнуляет состояние, запросы с протухшим токеном не идут (№4);
- переключение вход ↔ регистрация очищает все поля и ошибку (как `watch(isRegister)` в эталоне).

**Список чатов**
- превью последнего сообщения, время, бейдж непрочитанного (99+), pull-to-refresh, плашка `listError`;
- личный канал `ws/notifications/`: `new_message`, `chat_read`, `chat_deleted`, `chat_renamed`,
  `member_removed` — без перезахода в список;
- в открытом на переднем плане чате сообщение сразу подтверждается прочтением, в фоне — растит бейдж
  (либо/либо, как `applyNewMessage` в эталоне; раньше оба действия перезаписывали друг друга).

**Чат**
- лента в хронологическом порядке, `reverse: true`, дозагрузка старых страниц по жесту вверх
  без прыжка позиции; `hasMoreMessages` из поля `next`, а не из `length == 50` (№11);
- автоскролл к новому сообщению по изменению id последнего — и для WS-эха, и для REST-ответа (№12);
- если первой страницы не хватает на экран, история дополняется страницами, пока не появится скролл;
- системный «назад» закрывает чат через `PopScope` → `closeChat()` (№13);
- error-кадры бэкенда (`{error: ...}`: пустой текст, >5000 символов, анти-флуд 10/10 с) показываются
  плашкой, текст несообщённого сообщения остаётся в поле ввода (№9);
- `messages_read` фильтруется по `reader_id`: ✓✓ ставят только чужие прочтения, свои — нет (№10);
- перечитывание истории после reconnect: полная страница → замена ленты, частичная → добор в хвост
  и обновление `is_read` у известных (`reloadMessages`);
- presence в шапке: точка «в сети / не в сети» для личного чата, «N в сети / все не в сети» для группы;
- переименование GROUP: тап по названию (только админ) → инлайн-поле, Enter/✓ сохранить, ✕ отмена,
  `maxLength: 255` как на бэкенде;
- удаление чата: кнопка в шапке, первый тап взводит подтверждение, второй удаляет (GROUP — админ,
  PRIVATE — любой);
- статус соединения и человекочитаемая причина закрытия сокета в шапке.

**Группы**
- создание личного чата (идемпотентно) и группы — сразу с открытием созданного чата (№5);
- выбор участников по id (`Map<String, User>`): чекбоксы не сбрасываются между поисками, дублей в
  `member_ids` нет (№7); кнопка «Создать группу» неактивна без названия и показывает состав `(N)`;
- экран участников: presence-точка у каждого, чип «админ», строка «N в сети из M», удаление других
  (админу) и выход себя (№6); после выхода снимаются оба маршрута, а не только экран участников;
- добавление участников админом: debounced-поиск (300 мс) с отфильтровкой уже состоящих (№19 вернул
  `Api.addMember` вместе с UI).

**Сеть и устойчивость**
- WS-handshake с `Origin` (нативные платформы) — иначе бэкенд отвечает 403 (№1);
- backoff переподключений 1→60 с + джиттер ±30%: частота попыток ниже лимита бэкенда 20/мин,
  клиент сам себе не запирает подключения (№29);
- `isConnected` = «handshake завершён» (флаг `_isOpen`), поэтому при обрыве отправка уходит в
  REST-фолбэк, а не в мёртвый сокет (№28);
- refresh JWT перед handshake (`ensureFreshAccess`) и пробный `GET /users/me/` после 3 сорванных
  подключений: невалидная сессия возвращает к экрану входа вместо вечного «подключение...» (№16);
- возврат из фона (`AppLifecycleState.resumed`): перечитывается открытый чат, оживляются оба сокета,
  пришедшее считается прочитанным;
- ошибки не глушатся: плашки `sendError`/`loadError`/`detailsError`/`listError`, `_searchError`,
  `AuthState.error`, SnackBar через `onNotice` (№15).

**Профиль**
- чтение и `PATCH` своих полей; локальная проверка пустого телефона до отправки, блокировка
  двойного сохранения.

## Чего нет вовсе

- оптимистичная отправка и очередь сообщений при обрыве связи (отправка либо в WS, либо REST-фолбэк);
- `last_seen` («был в сети …») — поле отдаётся только на `/users/me/` про самого себя,
  для собеседника и участников этих данных в API нет;
- индикатор «печатает…», пересылка, вложения, редактирование и удаление сообщений — на бэкенде тоже нет;
- push-уведомления;
- локализация (строки захардкожены по-русски) и тёмная тема (кроме seed Material 3);
- deep links, именованные маршруты, state restoration;
- CI.

## Отличия от веб-эталона (осознанные)

| # | Клиент | Эталон | Зачем |
|---|--------|--------|-------|
| E1 | backoff 1→60 с + джиттер | фиксированные 2 с | 30 попыток/мин превышали лимит 20/мин, клиент запирал себя сам (№29) |
| E2 | `ensureFreshAccess()` до handshake | токен из localStorage as is | отказ 4001 приходит до `accept`, WS-кода клиент не видит (№16) |
| E3 | `_probeAuth()` после 3 сорванных handshake | — | тот же невидимый отказ: отличить мёртвую сессию от сетевой |
| E4 | `revive()` сокета чата при возврате из фона | оживает только личный канал | ОС рвёт соединения спящего приложения, а 4009 — в `noReconnectCodes` |
| E5 | цикл дозаполнения экрана с проверкой «страница не пришла → break» | тот же цикл без проверки | без неё пустой ответ крутил бы запросы до упора в лимит scope `read` |
| E6 | `PopScope(canPop: false)` | `Esc` → `closeChat()` | мобильный аналог; цена — нет предпросмотра анимации жеста |

Ограничение, унаследованное от эталона: новое сообщение всегда прокручивает ленту вниз, даже если
пользователь читает историю. «Прилипание только у нижней кромки» — правка в обе реализации сразу,
в список не входила.

## Платформы

Кроссплатформенность заявлена, но конфиги целей не доведены — release-сборки не выйдут в сеть:

- **Android**: в `android/app/src/main/AndroidManifest.xml` нет `INTERNET` (он только в debug/profile)
  и нет `usesCleartextTraffic` для HTTP (№21);
- **macOS**: в `DebugProfile.entitlements` и `Release.entitlements` нет
  `com.apple.security.network.client` — исходящие соединения блокирует песочница (№22);
- **iOS**: в `Info.plist` нет `NSLocalNetworkUsageDescription` (нужно для обращения к IP в локальной
  сети на iOS 14+) (№23);
- **web**: не заработает без правок бэкенда — `CORS_ALLOWED_ORIGINS` разрешает только `:5173`,
  а `Origin` с порта Flutter-web не входит в `ALLOWED_HOSTS`; заголовки WS на web недоступны в принципе (№24);
- **Linux/Windows**: ограничений нет, работают как есть.

Имя пакета — `lost_dream_messenger_client`, отображаемые имена — «Lost Dream Messenger» (№25).
Хвост: `MaterialApp.title` в `lib/main.dart:70` всё ещё «Мессенджер» — это подпись в переключателе
задач Android и `document.title` на web (№36). Идентификаторы сборки (`applicationId`, `namespace`,
`PRODUCT_NAME`, `BINARY_NAME`) оставлены как есть: их переименование — перенос пакетов и перевыпуск
артефактов, отдельная задача релизной подготовки.
