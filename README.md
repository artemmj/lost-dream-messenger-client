# Lost Dream Messenger — Flutter-клиент

Кроссплатформенный клиент (Android, iOS, macOS, Windows, Linux, web) к Django-бэкенду
[lost-dream-messenger](https://github.com/artemmj/lost-dream-messenger): личные и групповые чаты, real-time через
WebSocket, presence, счётчики непрочитанного, JWT-авторизация.

До этого репозиторий был нативным Android-приложением на Kotlin/Compose. Оно удалено из рабочего
дерева, но лежит в git-истории (коммит `433543b`, каталог `app/`) и может служить образцом:
там контракт бэкенда выверен (порядок сообщений, `Origin` для WS, личный канал уведомлений).

> **Статус: рабочий прототип.** Основной сценарий «войти → список чатов → открыть чат →
> отправить / получить» работает, включая real-time: критичные дефекты №1–№7 и дебаунс поиска
> (№8) исправлены, блок «Гигиена» (№17–№20) закрыт — `flutter analyze` и `flutter test` больше
> не падают, — а устаревшие нативные имена в метаданных целей заменены на «Lost Dream Messenger»
> (№25). Стабильность real-time на двух клиентах починена: статус «на связи» действительно
> появляется, отправки не теряются, переподключение больше не запирает себя лимитом бэкенда
> (№3-хвост, №28, №29). Сессия больше не «умирает молча»: access-токен обновляется до
> WS-handshake, а невалидная авторизация возвращает к экрану входа вместо вечного
> «подключение...» (№16); ошибка загрузки истории показывается в чате, а не глотается (№15,
> частично). Остальные проблемы и полный разбор — в [AGENTS.md](AGENTS.md): карта файлов,
> контракт бэкенда, известные дефекты с указанием строк.

## Запуск

1. Поднять бэкенд: `cd ../lost-dream-messenger-server && docker compose up` (Postgres, Redis, Daphne на `:8000`).
2. Проверить хост в `lib/config.dart` (`AppConfig.host`):

   | Цель | Хост |
   |------|------|
   | Эмулятор Android | `10.0.2.2:8000` (уже по умолчанию) |
   | Симулятор iOS / macOS | `127.0.0.1:8000` |
   | Реальное устройство | IP машины в локальной сети |

3. `flutter pub get && flutter run -d <device>`.

Хост зашит константой времени компиляции, поэтому смена окружения — это правка файла. Перевод на
`String.fromEnvironment` + `--dart-define=API_HOST=...` в списке TODO.

## Что работает

- вход и регистрация, хранение пары JWT, авто-refresh по 401 с одним повтором запроса;
- реактивный переход Логин ↔ Список чатов: экран выбирает `_Boot` по состоянию `AuthState`,
  корректный вход и выход из аккаунта с полной остановкой сокетов и очисткой состояния;
- список чатов: превью последнего сообщения, время, бейдж непрочитанного (99+), pull-to-refresh;
- чат: история в хронологическом порядке с дозагрузкой старых страниц, отправка через WS
  с фолбэком в REST, отметка прочтения при открытии, галочки ✓/✓✓, статус соединения и
  человекочитаемая причина закрытия сокета в шапке, плашка ошибки загрузки истории;
- WebSocket: handshake с `Origin` (нативные платформы), переподключение с экспоненциальным
  backoff'ом 1→60 с (не превышает лимит бэкенда 20 подключений/мин и не запирает себя), обработка
  кодов закрытия 4003/4004 (удаление чата из списка), refresh JWT перед handshake и сброс
  сессии с возвратом к экрану входа при невалидном токене (4001, включая невидимые отказы
  до accept — различаются пробным `GET /users/me/`);
- личный канал `ws/notifications/`: новое сообщение в другой чат, сброс бейджа, удаление и
  переименование чата, исключение из чата — без перезахода в список;
- создание личного чата (идемпотентно) и группы — сразу с открытием созданного чата;
- выбор участников группы: состояние хранится по id пользователя, чекбоксы не сбрасываются
  между поисками, дубли в `member_ids` исключены;
- поиск пользователей с отменяемым дебаунсом на `Timer` (не сжигает лимит `search`);
- экран участников группы: роль «админ», удаление участников (админу), выход из чата (себе);
- профиль: чтение и `PATCH` своих полей, выход из аккаунта.

## Чего нет вовсе

- переименование группы и удаление чата из UI (клиентских методов нет — раньше были мёртвыми,
  удалены при починке №19; эндпоинты бэкенда живы, методы вернутся вместе с UI);
- добавление участника в группу (`Api.addMember` удалён как мёртвый код);
- отображение presence: `onlineUsers` собирается из `initial_presence`/`user_status`, но не рисуется;
- `last_seen` в профиле и в списке чатов (поле не парсится, вернётся с presence);
- пагинация списка чатов и учёт `next` в истории (видно только первые 50);
- оптимистичная отправка, очередь сообщений при обрыве связи, индикаторы «печатает»;
- push-уведомления, локализация (строки захардкожены по-русски), тёмная тема вручную (только seed Material 3);
- тесты: только смоук-тест `test/widget_test.dart` (без сессии показывается экран входа);
  unit-тестов `ChatState`/`Api`, widget-тестов экранов и CI нет.

## Платформы

Кроссплатформенность заявлена, но конфиги целей не доведены — release-сборки не выйдут в сеть:

- **Android**: в `android/app/src/main/AndroidManifest.xml` нет `INTERNET` (он только в debug/profile)
  и нет `usesCleartextTraffic` для HTTP;
- **macOS**: в `macos/Runner/DebugProfile.entitlements` и `Release.entitlements` нет
  `com.apple.security.network.client` — исходящие соединения блокирует песочница;
- **iOS**: в `Info.plist` нет `NSLocalNetworkUsageDescription` (нужно для обращения к IP в локальной
  сети на iOS 14+);
- **web**: не заработает без правок бэкенда — `CORS_ALLOWED_ORIGINS` разрешает только `:5173`,
  а `Origin` с порта Flutter-web не входит в `ALLOWED_HOSTS` (WS снова 403);
- **Linux/Windows**: ограничений нет, работают как есть.

Имя пакета в `pubspec.yaml` — `lost_dream_messenger_client`, а все отображаемые имена
(`android:label`, `CFBundleDisplayName`/`CFBundleName`, `<title>` и манифест web, `description`
в `pubspec.yaml`) — «Lost Dream Messenger». Идентификаторы сборки (`applicationId`, `namespace`,
`PRODUCT_NAME`, `BINARY_NAME`) оставлены как есть: их переименование — это перенос пакетов и
пересборка артефактов, отдельная задача для релизной подготовки.
